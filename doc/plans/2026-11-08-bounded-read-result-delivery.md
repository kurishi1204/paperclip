# Bounded native read-result delivery

An oversized native read result must fail explicitly without becoming an unknown write. The existing durable command limit and all authority checks remain unchanged.

The shared protocol catalog is the authority for sideEffectClass=read. Only when such an operation has resolved and queueCommand rejects its result as command_payload_too_large before append/send does the controller queue one bounded error for the original call. It includes the omitted result byte count and digest, omits the body, and directs the caller to an existing narrower/paginated/artifact read path. It is an error, not a successful read response, and it does not repeat the operation.

The original input, source event, correlation and command-result acknowledgement remain required. Once the explicit error is durably delivered, normal provider drain and suspension can proceed; an unfinished read response must not poison later work. Oversized write results, unknown operations, failed persistence, a full journal and uncertain dispatcher failures retain the original fail-closed quarantine and outcome-reconciliation behavior. There is no automatic write replay, permission change or relaxed process-cleanup proof.

Verification uses the real authenticated encrypted PRP channel: an oversized synthetic revision read returns the bounded error, an ordinary following write runs once, both deliveries settle, and reopening the controller does not redispatch. Negative tests retain quarantine for a write and an uncatalogued operation. This change does not claim that all history fits a single response or that a tool error is business acceptance.

Settlement requires a completed command with an exact original callId and a known provider receipt: delivered, settled_after_turn, or duplicate. Codex durably records an after-turn result and rejects a conflicting duplicate before emitting these latter receipts; they are not evidence of live-model delivery. Missing, queued, malformed or another call's receipt remains unsettled after reopen. Diagnostics expose settledWithoutLiveDelivery separately. Provider drain and suspension proof remain independently required, so journal settlement alone cannot certify a reusable provider.

Assigned application tools cannot shadow catalog read operations: the production gateway maps every raw app tool name into an app_-prefixed name with a digest, and its two on-demand wrapper names are separate from native catalog operations. The namespace proof covers every current native operation and preserves the original gateway. No extra routing restriction or permission is introduced.

The document-history reader now exposes limit (default 5) and a cursor containing the original documentId and an exclusive beforeRevisionNumber through both catalog surfaces and both server authorities. The database query itself is limited; a page includes hasMore and nextCursor rather than hiding older revisions. For large bodies use limit=1, then follow that cursor. Assigned same-version QA remains restricted to its exact fixed revision regardless of paging input. An individually oversized revision still returns the explicit transport error; no body is silently shortened. The real database fixture pages complete synthetic 180 KB bodies across concurrent new writes and checks every revision ID once.

The cursor binds the original document identity in the database query. If that history disappears, the next page fails explicitly as cursor_expired; deleting and reusing the same key cannot splice a replacement document into the old history. Both readers honor the full advertised 1..200 limit independently of the unrelated common task-history limit. Real database checks cover 150/200 and deletion/recreation.
