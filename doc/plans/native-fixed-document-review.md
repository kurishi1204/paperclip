# Fixed document QA through the dedicated task tool

An employee could discover the interaction REST endpoint but could not create a named document review through it: generic `call_api` deliberately rejects interaction mutations. The dedicated `request_human_input` tool did not accept or forward a reviewer, so callers fell back to separate review tasks.

For standard-mode business tasks the dedicated tool now accepts an optional `addresseeAgentId` on a confirmation bound to the exact saved current-task documentId/key/revisionId. The normal interaction service checks company membership, independent/invokable addressee, current document identity and resolver governance. Under the creation locks it also rejects a document creator/latest editor as reviewer and a human-only company cap, rather than creating an unusable card. It receives no caller-supplied or synthesized resolver-policy override. The reserved plan document, planning mode, governed actions, ordinary human questions and Ask mode cannot use the named-review option. Existing human-only decisions keep their resolver restriction. Generic REST creation and decision escapes remain denied. A pending employee document review is isolated from unrelated confirmation replacement and the periodic sibling-card sweeper. Same document/revision/reviewer requests with another key return an explicit conflict pointing at the existing review; the original stable key remains idempotent across a fresh authorized run without a second created event or any change to the original sourceRunId. Stale-document and explicit lifecycle expiry retain their existing paths.

The scenario simulator does not implement live employee review dispatch. It returns an explicit unsupported result for a named reviewer instead of silently creating a human card without that reviewer. Live/scenario descriptors and generated catalog/contract projections are updated through their normal generators.

Qualification keeps old failed attempts, tests the actual saved addressee against the old authority, and exercises the real isolated database/HTTP fixture. Production acceptance still requires same-head independent review, normal CI/build and an actual existing-employee fixed-version QA handoff; local checks alone do not complete it.
